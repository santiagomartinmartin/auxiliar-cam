# Tema 19. Bases de datos: Access. Principales funciones y utilidades. Tablas. Consultas. Formularios. Informes. Relaciones. Importación, vinculación y exportación de datos. Power BI

> **Versión de referencia:** **Access de Microsoft 365, versión de escritorio**. Power BI se pregunta a nivel de **conceptos generales**.

## 1. Conceptos básicos de Access

- **Access** es un **sistema gestor de bases de datos relacionales** de escritorio.
- **Base de datos relacional:** los datos se guardan en **tablas** relacionadas entre sí mediante **campos comunes**.
- **Archivo:** **.accdb** (formato predeterminado desde Access 2007; el antiguo era **.mdb**). También **.accde** (versión compilada, sin acceso al diseño) y **.laccdb** (archivo de **bloqueo** temporal mientras la base está abierta).
- **Una instancia** de Access solo puede tener **una base de datos abierta** a la vez (para abrir otra hay que iniciar otra instancia).
- **Panel de navegación:** muestra los **objetos** de la base de datos.

| Objeto | Función |
|---|---|
| **Tablas** | **Almacenan los datos** (es el único objeto que los guarda directamente) |
| **Consultas** | **Buscan, filtran, combinan, calculan o modifican** datos de una o varias tablas |
| **Formularios** | **Introducir, ver y modificar** datos de forma cómoda |
| **Informes** | **Presentar e imprimir** datos con formato |
| **Macros** | Automatizar acciones sin programar |
| **Módulos** | Código **VBA** |

## 2. Tablas

### 2.1. Estructura

- **Registro:** cada **fila** (todos los datos de un elemento: un cliente).
- **Campo:** cada **columna** (un dato concreto de todos los registros: el teléfono).
- **Clave principal:** campo (o conjunto de campos) que **identifica de forma única e inequívoca** cada registro; **no admite valores repetidos ni vacíos**.
- **Clave externa:** campo de una tabla que contiene la **clave principal de otra** para relacionarlas.

### 2.2. Vistas

- **Vista Hoja de datos:** ver e introducir datos (filas y columnas).
- **Vista Diseño:** **crear y definir los campos** de la tabla, sus **tipos de datos** y **propiedades**, y la **clave principal**.

### 2.3. Tipos de datos

| Tipo | Uso |
|---|---|
| **Texto corto** | Texto o números que no se calculan, hasta **255 caracteres** |
| **Texto largo** | Textos extensos (antes «Memo»), con formato enriquecido |
| **Número** / **Número grande** | Valores numéricos para cálculos (Byte, Entero, **Entero largo**, Simple, Doble, Decimal) |
| **Fecha/Hora** y **Fecha/Hora extendida** | Fechas y horas |
| **Moneda** | Importes con precisión fija |
| **Autonumeración** | Número **único** que Access **asigna automáticamente** a cada registro nuevo (secuencial o aleatorio); se usa como **clave principal** y **no se puede modificar** |
| **Sí/No** | Valores booleanos |
| **Objeto OLE** | Objetos de otros programas |
| **Hipervínculo** | Direcciones web, de correo o de archivos |
| **Datos adjuntos** | Archivos adjuntos al registro |
| **Calculado** | Resultado de una expresión con otros campos |
| **Asistente para búsquedas** | Crea un campo que elige valores de **una lista** o de **otra tabla** |

### 2.4. Propiedades de los campos

**Tamaño del campo**, **Formato** (cómo se **muestra** el dato), **Lugares decimales**, **Máscara de entrada** (patrón para **introducir** datos, por ejemplo un DNI), **Título** (etiqueta que se muestra), **Valor predeterminado**, **Regla de validación** y **Texto de validación**, **Requerido**, **Permitir longitud cero** e **Indexado** (con o sin duplicados).

## 3. Relaciones

- **Herramientas de base de datos → Relaciones:** se arrastra el campo común de una tabla a otra.
- **Tipos:**

| Relación | Ejemplo | Cómo se implementa |
|---|---|---|
| **Uno a uno** | Empleado – ficha médica | Campo común clave principal en ambas |
| **Uno a varios** | **Clientes – Pedidos** (un cliente, muchos pedidos) | **Clave principal** en la tabla «uno» (Clientes) y **clave externa** en la tabla «varios» (Pedidos), con el **mismo tipo de datos** (si la clave es **Autonumeración**, la externa es **Número – Entero largo**) |
| **Varios a varios** | Alumnos – Asignaturas | Con una **tabla de unión** intermedia y dos relaciones uno a varios |

- **Exigir integridad referencial:** impide introducir en la tabla relacionada un valor de clave externa que **no exista** en la tabla principal, y **eliminar o modificar** un registro principal que tenga **registros relacionados**.
  - **Actualizar en cascada:** al cambiar la clave principal, se cambian las claves externas relacionadas.
  - **Eliminar en cascada:** al borrar un registro principal, se borran sus registros relacionados.

## 4. Consultas

### 4.1. Diseño

**Crear → Diseño de consulta** (cuadrícula **QBE**) o **Asistente para consultas**. Filas de la cuadrícula: **Campo**, **Tabla**, **Orden**, **Mostrar**, **Criterios** y **O**. Las consultas guardan la **definición**, no los datos: muestran siempre los datos actuales de las tablas.

### 4.2. Tipos

| Tipo | Qué hace |
|---|---|
| **Selección** | **Muestra** los registros que cumplen unos criterios (la más común) |
| **Parámetros** | **Pide un valor** al ejecutarse (criterio entre corchetes: `[Introduzca la ciudad]`) |
| **Totales** | Agrupa y calcula (suma, promedio, cuenta…) |
| **Referencias cruzadas** | Resume datos en formato de **tabla de doble entrada** |
| **Creación de tabla** (acción) | Crea una **tabla nueva** con el resultado |
| **Datos anexados** (acción) | **Añade registros** de una tabla a **otra existente** (por ejemplo, copiar «ClientesNuevos» en «Clientes») |
| **Actualización** (acción) | **Modifica** datos existentes: el nuevo valor se escribe en la fila **«Actualizar a»** |
| **Eliminación** (acción) | **Borra** los registros que cumplen los criterios |
| **SQL específicas** | Unión, paso a través y definición de datos |

Los **asistentes** permiten crear consultas **sencillas**, de **referencias cruzadas**, de **búsqueda de duplicados** y de **búsqueda de no coincidentes**.

## 5. Formularios

- Sirven para **introducir, consultar y modificar** datos registro a registro.
- **Crear:** Formulario, **Asistente para formularios**, Diseño del formulario, formulario en blanco, **Formulario dividido** (formulario + hoja de datos), **Varios elementos**, **subformularios**.
- **Vistas:** **Formulario** (uso), **Presentación** (ajustar el diseño viendo datos reales) y **Diseño** (estructura detallada).
- **Controles:** etiquetas, cuadros de texto, **cuadros combinados** y de lista, casillas, botones de comando, imágenes.

## 6. Informes

- Sirven para **presentar e imprimir** datos con formato, **agrupados**, **ordenados** y con **totales**.
- **Crear:** Informe, **Asistente para informes**, Diseño de informe, informe en blanco y **Etiquetas** (el **Asistente para etiquetas** de la pestaña **Crear**).
- **Vistas:**

| Vista | Uso |
|---|---|
| **Vista Informe** | Ver el informe en pantalla (permite filtrar y copiar) |
| **Vista preliminar** | Ver cómo se **imprimirá** (páginas, márgenes) |
| **Vista Presentación** | **Modificar el diseño viendo los datos reales** (ancho de columnas, formato, agrupaciones) |
| **Vista Diseño** | Control completo de **secciones** y controles, **sin datos reales** |

- **Secciones:**

| Sección | Aparece |
|---|---|
| **Encabezado de informe** | **Una sola vez**, al **principio** del informe (portada, título) |
| **Encabezado de página** | En la parte superior de **cada página** |
| **Encabezado de grupo** | Al principio de cada grupo |
| **Detalle** | Una vez por **cada registro** |
| **Pie de grupo** | Al final de cada grupo (subtotales) |
| **Pie de página** | En la parte inferior de **cada página** (número de página) |
| **Pie de informe** | **Una sola vez**, al **final** (totales generales) |

## 7. Importación, vinculación y exportación

**Pestaña Datos externos.**

| Operación | Efecto |
|---|---|
| **Importar** | **Copia** los datos externos en una tabla de Access (nueva o existente). Los cambios posteriores en el origen **no** se reflejan |
| **Vincular** | Crea una **tabla vinculada**: los datos **permanecen en el origen** y los cambios se ven en **ambos lados** |
| **Exportar** | Envía tablas, consultas, formularios o informes a **Excel**, texto, **PDF/XPS**, Word (RTF), XML, otra base de Access o SharePoint |

- **Orígenes:** Excel, otra base de Access, **archivos de texto** (delimitados o de ancho fijo), XML, **ODBC** (SQL Server y otros), **listas de SharePoint**, Outlook.
- **Guardar pasos de importación** (o de exportación): guarda la operación para **repetirla** más tarde **sin pasar de nuevo por el asistente** (**Importaciones guardadas**).

## 8. Herramientas de mantenimiento

- **Compactar y reparar base de datos:** **reduce el tamaño** del archivo eliminando el espacio no utilizado y **repara** daños.
- **Dividir la base de datos:** separa los **datos** (back-end) de las **consultas, formularios e informes** (front-end) para el uso compartido.
- **Cifrar con contraseña**, **documentador de base de datos**, **analizador de rendimiento** y **analizador de tablas**.

## 9. Power BI

### 9.1. Qué es

**Power BI** es la plataforma de **inteligencia de negocio (business intelligence)** de Microsoft para **conectar, transformar, modelar y visualizar datos** de múltiples orígenes y crear **informes y paneles interactivos** que se comparten en la organización.

### 9.2. Componentes

| Componente | Uso |
|---|---|
| **Power BI Desktop** | Aplicación gratuita de Windows para **crear informes** (archivos **.pbix**) |
| **Servicio Power BI** | Plataforma **en la nube** (app.powerbi.com) para **publicar, compartir**, crear **paneles**, programar la **actualización** de datos y colaborar en **áreas de trabajo** |
| **Power BI Mobile** | Aplicaciones para móvil y tableta |
| **Power BI Report Server** | Servidor de informes **local** |
| **Puerta de enlace de datos local** | Conecta el servicio con datos que están **en la red de la organización** |

### 9.3. Flujo de trabajo

1. **Obtener datos** (Excel, CSV, bases de datos, SharePoint, servicios web…).
2. **Transformar** con **Power Query** (limpiar, combinar, cambiar tipos).
3. **Modelar:** **relaciones** entre tablas y cálculos con **DAX** (**medidas** y **columnas calculadas**).
4. **Visualizar:** **informe** con páginas, gráficos, tablas, **matrices**, **tarjetas**, mapas y **segmentaciones**; **filtros** de objeto visual, página e informe; **obtener detalles** (drill-down).
5. **Publicar** en el servicio y **compartir** (paneles, aplicaciones, Teams).

**Vistas de Power BI Desktop:** **Informe**, **Tabla** (datos), **Modelo** y **Vista de consultas DAX**.

### 9.4. Conceptos clave

- **Informe:** una o varias **páginas** de objetos visuales interactivos basadas en **un modelo semántico** (antes «conjunto de datos»).
- **Panel (dashboard):** **una sola página** del **servicio** con **iconos anclados** de uno o varios informes, para ver de un vistazo los indicadores.
- **Preguntas y respuestas (Q&A)** y **Copilot:** consultas en **lenguaje natural**.
- **Seguridad de nivel de fila (RLS):** cada usuario ve solo los datos que le corresponden.
- **Licencias:** gratuita, **Pro** y **Premium** (o capacidad de **Fabric**) para compartir contenidos.
